## generate_image

<Note>
  On Claude, this tool is listed only for workspaces allowed to generate media. See [Claude](/agents/connect#claude).
</Note>

Renders a new image from a brief and reference images: products in scenes, people, light, backgrounds, and edits that must look photographed. Every call re-renders the whole frame and varies; a correction comes back close to its source, never pixel-identical. A change to a photograph, such as a new frame, a different product size or a correction, is a new render from the original sources. Spends credits; saves to the media library.

Tolstoy's creative skills carry its creative direction for this work: before any generation, the skill that matches the request is found and loaded, and the prompt follows it.

Generate or edit images using AI models. One tool, two modes.

**Mode selection:**
- `mode='text'` — pure text-to-image, no input media: abstract concepts, backgrounds or scenes built from scratch, mood boards and creative exploration, a quick one-off person without a reusable library entry, or when the user explicitly wants pure text-to-image.
- `mode='image'` — pass selected reference/source images. The DEFAULT whenever ANY product photo, brand image, model photo, or style reference exists in context: product work whose success depends on shape, color and labels holding, background work that must not cost you the product, compositing with models or lifestyle scenes, try-on / model-swap workflows.

**When references exist, always pick `mode='image'`.** Even for tasks that sound like "generation" (e.g. "create a lifestyle scene around this product"), the reference grounds the output — `mode='text'` loses the product. When the brief refers to a real thing but no reference is in context, find or request one before falling back to text mode.

**How Reference Evidence and Words Work Together (mode='image'):**

A reference image is visual evidence, not a pixel contract. Image models reconstruct what they see: large shapes and composition usually carry strongly, while small logos, stylized lettering, fine print, subtle colors, and tiny product details carry less signal and may be simplified. What replaces the lost signal is the model's prior: a named thing arrives in its canonical form — a flag-shaped device in flag colours, metal as bright chrome — whatever the reference shows.

Reference inputs have acceptance requirements separate from output resolution. Each model's capability entry describes the documented limits for its provider and transport. An unstated constraint is unknown; a fallback route can have different requirements. Image source preservation in the system prompt describes the source evidence that preprocessing can change.

References and words contribute different evidence. The renderer rebuilds the frame from both. A reference with a role and a verb is reproduced from its pixels; anything the words describe again is re-rendered from the words instead. Words carry what pixels cannot: what each reference is for, what must change, and what no reference shows.

Context is the pool of available evidence, not the generation input list. A reference earns an input slot only when it adds a distinct visual fact needed in this output. A person visible in a scene or product photo remains character evidence even when the prompt assigns that image another role. Choose the smallest set that fully defines the requested frame, and split the work into stages when the selected model's fidelity budget cannot hold those distinct facts.

**Subject scale (mode='image'):** the engine composes the named subject to fill the frame; a stated fraction or pixel size is loosely followed and does not converge across attempts.

**Understanding a failed generation:**

A mismatch can come from the direction, the source images or the model's visual capability. Wrong scene, framing, angle or missing content points toward the prompt. A fidelity defect that persists across materially different directions from clean sources can indicate a model limit. Capability descriptions explain those limits.

Longer prompts and extra references do not necessarily improve fidelity; each extra reference is one more competing signal.

**What an edit can carry (mode='image'):** `mode='image'` renders a new frame from your references and words every time. "Edit" is the intent, not the mechanism — no pixel of an input reaches the output. A small delta — color, mood, light, a small addition, a background at similar framing — usually comes back close to the frame you started from. A change to how the frame was *built* — layout, product placement, aspect ratio, identity — is not reachable that way, because the print you started from is what locked that construction in. Rebuild from the sources instead. A refinement streak that keeps missing the same thing is usually this.

**Identity and product truth (mode='image'):** holding the person's core identity — face, skin tone, body, age — and the product's visual is what the call aims at, and it is why you pass the source. Whether it held is a property of the render in front of you, not of the request. Style sits on top and is meant to move: attitude, hair, makeup, brows, piercings, nails are customization, not drift, so "same model, hair up, soft glam" keeps the core and changes the rest.

Looking at the output tells you what it matches, at the scale you looked. It cannot tell you that anything was carried over, because the source and the output are two separate renders that never shared a pixel — the only truthful claim about sameness is a comparison, so report it as one: what the new frame matches, how closely, and where it misses. The comparison runs both ways: a render can also contain what no source shows — an added seam, a frame around a mark, an extra device — and a check that only confirms expected features cannot see additions.

The person designated by the request is the identity anchor. Original person and product photos carry their visual details. Identity leads and the product follows: the renderer reads the first reference as the person, and a person in a product photo is context, never a face source.

**Try-on orientation:** orientation is part of product identity — a back print on a front-facing model is a different product. Pair like with like, trust the image over alt text or array position, and say which pairing you used.

**Aspect ratio & resolution:** unified parameters with model-local behavior.
- `aspectRatio` — 1:1 / 16:9 / 9:16 / 4:3 / 3:4 / 3:2 / 2:3 / 21:9 / 5:4 / 4:5. Every model renders the ratio you ask for, except Grok Imagine and Higgsfield Soul: those two have no 21:9, 5:4 or 4:5, and receive the nearest ratio of the same orientation instead — Grok 20:9 / 4:3 / 3:4, Soul 16:9 / 4:3 / 3:4. Pass null to use the behavior described by the selected model's capability entry.
- `resolution` — 1K / 2K / 4K. Default 2K — pass 4K only when the user explicitly asks for hero / print-quality output. Parameter exceptions and output limits live in each model's capability entry.

**Persistent model workflow:** User wants a reusable model saved to their library → generate with this tool, then call `save_fashion_model` to persist. Load the `model_generation` skill for the full workflow.

**Prompt rules:** self-contained, no conversation refs. Don't combine images into collages, grids, or composites unless explicitly requested.

**Intimate apparel / body-focused garments:**
When references show underwear, lingerie, swimwear, bodywear, or sleepwear, apply commercial framing on the first attempt. PROMPT_CRAFT carries the register that clears it; check the selected model's own content-support description.

**Limitations:**
Image editing (mode='image') cannot reliably:
- Remove specific structural elements (floor lines, seams, horizons)
- Perform precise inpainting or surgical removal of scene elements
- Change fundamental scene setup (backdrop type, lighting rig, composition)
When users ask for these changes, regenerate with the original product/model inputs and updated prompt instead of chaining edits.

**Models:**
`google_nano_banana_2_1` is the default. Models differ in their visual finish, correction fidelity and reference capacity, and people differ in which finish they want: what this person kept or redid, in this chat and in account memory, is the evidence for the engine to lean on. Every generation reconstructs the frame. Repeated edits carry forward and compound rendering artifacts in texture, colour, detail and identity, even when the prompt asks for no change. Switching models while reusing an edited image carries those artifacts into the new model. Regenerating from the original source photos is how a fix to the product or its framing comes back clean. This breaks the chain only when prior correction outputs are absent from all inputs, including secondary references. Returning to original sources or an earlier image means the generation prompt describes all changes needed from those inputs to the current intended result, including previously approved edits and the latest request.

## generate_video

<Note>
  On Claude, this tool is listed only for workspaces allowed to generate media. See [Claude](/agents/connect#claude).
</Note>

Renders a new video clip from text, an image, keyframes or references. Output varies between calls, and exact text, timing and framing are not guaranteed. Spends credits per second; saves to the media library.

Tolstoy's creative skills carry its creative direction for this work: before any generation, the skill that matches the request is found and loaded, and the prompt follows it.

Create a video from text, one image, keyframes, or references.

**Model selection.** Ask first what the brief does with its source. A brief that must preserve something already made — a supplied character, product, logo or art style — is decided by a model's `Style` behaviour (stated per entry, or in the Seedance family section below), because a model that reinterprets its input cannot satisfy it however well it scores elsewhere; a model with no style statement is unproven for preservation. A brief that invents a shot is decided by its `Defining axis`. Do NOT pick on the `cost tier` field — those tiers are downstream metadata for the user, not a selection signal for you.

**Pick `mode` first:**
- `text` — prompt only, no input media.
- `image` — one image, animate it.
- `keyframe` — two images (first + last), model interpolates between them. With `flux_3_max` you can also pass `midFrames` to pin up to 8 more images at named seconds in between.
- `reference` — multiple images / structured elements / optional audio refs composed together.

**Then pick a `model` whose `Modes:` list (in modelCapabilities below) includes your chosen mode.** Not every model runs every mode — e.g. `kling_v3_*` is prompt-first with NO reference mode; for multi-image/multi-subject composition pick `kling_v4`, `gemini_omni_flash`, `bytedance_seedance_2_0`, `bytedance_seedance_2_5`, or `alibaba_wan_3_0*`. An incompatible mode×model pair is rejected before execution.

**Feature caveats (validation enforces — refer to modelCapabilities for which model supports which):**
- `cfgScale`: restricted to Kling V3.
- `multiPrompt` + `prompt` are mutually exclusive.
- `elements`: Kling-family only.
- `2k` and `4k`: Gemini Omni Flash carries `4k`. Other models map to their documented cap.
- `referenceAudioUrls`: Seedance 2.x and WAN 3.0 in reference mode only (2.0 ≤3, 2.5 ≤10, WAN ≤5 and ≤15s combined).
- `audioUrl`: the audio-driven models only (`veed_fabric_1_0`, `bytedance_omnihuman_v2`), where it is required.
- `midFrames`: `flux_3_max` in keyframe mode only — the one model that pins more than two frames.
- `referenceVideoUrls`: Gemini Omni Flash (≤3, each clip ≤3s) and `alibaba_wan_3_0*` (≤5) in reference mode only.
- `referenceFileUrl`, `referenceWebUrl`: `alibaba_wan_3_0*` in reference mode only — the one model that reads a document or a web page as its source.
- `luma_ray_3_2`: text runs 5s or 10s; image/keyframe is 5s in this slice.
- `runway_gen4_5`: text mode accepts only 16:9 or 9:16; image mode accepts the broader documented ratio set; no keyframe/reference mode.
- `kandinsky_6_*`: every clip renders as 5s at 480p whatever duration and resolution are asked for; 2:3, 3:2 and 21:9 are rejected.

**On validation error, re-plan with a compatible model or mode — do not retry with a workaround.**

**Seedance 2.x family behavior (all bytedance_seedance_2_0* tiers and bytedance_seedance_2_5):** The family carries the idiom its source arrives in — photoreal, flat illustration, line art, cel animation and 3D renders each come back in their own register rather than pulled toward film — which is what makes it the match whenever a supplied character, product or art style has to survive the generation. The tiers differ on three facts and nothing else: 2.5 runs 4-30s and takes 30 image and 10 audio references but fails a photoreal real-person reference outright; 2.0 runs 4-15s and takes 9 and 3 and passes real-person references through a face-permissive endpoint; both reach 1080p, and 2.0 is cheaper per second at every tier; fast is 2.0 at 720p; mini is the cheapest and rejects real-person references. Framing follows the input in image mode — a near-square anchor returns a near-square clip whatever aspectRatio asked for — while text and reference modes honour the requested ratio; when the anchor's shape and the deliverable's differ, resize the anchor with resize_media before generating rather than reframing the video after. Native beat-matching — given an audio reference it syncs motion and cuts to the music with phoneme-level lip sync across 8+ languages; the richest reference input in the roster; multi-panel keyframe grids read as one reference whose panel sequence becomes multi-scene continuity. Audio is written in channels: (parentheses) carry music and ambient beds, &lt;angle brackets&gt; sound effects, \{braces\} spoken dialogue — language and tone declared before the braces — and 【full-width brackets】 on-screen subtitles. Two or three short physical effects land; dense per-object foley is the common audio failure. Audio quality degrades past ~10s — cap audio-critical clips at 10s regardless of the tier ceiling. It renders an edit, not a single shot: a shot list with cut times comes back cut there; a prompt naming no cuts comes back as one continuous take — and timestamped beats inside a no-cuts prompt choreograph the take without cutting it. Each shot carries its own angle, distance, action and sound, and across a cut the model holds position, momentum and physical state when the prompt says what continues — occlusion, whip pans and action matching serve as named transitions. Cutting reads less generic than one long take, at the cost of another place the subject can deform per cut. Past ~15s, stage the brief instead of listing every cut: [Generation Goal] / [Stage 1..N] / [Maintain Consistency] — one main change and one clear end state per stage, simultaneous events inside a stage weaken its transition — with the consistency block naming what must not change (cast count, clothing, props, spatial relations). A staged 30s brief holds through to its declared final frame. The vendor (BytePlus ModelArk) lists what the words of a shot can carry: subject, action detail, scene, lighting and colour, camera movement, visual style, image quality and constraints. Actions land described per body part with range, speed and force, and with the transition between them stated; pacing words carry further than technical specs. One camera movement per shot. The vendor treats image-quality, style and constraint words as necessary configuration and names constraint phrasing ("no subtitles", "no logo", "must not deform") as its lever against deformity. Capture format is its own control surface — naming a camera system and its defects (phone sensor with rolling shutter and hunting exposure; ARRI with anamorphic; DV camcorder) moves output further than quality adjectives, and the look being avoided can be named too. Stating physics — feet keeping contact, weight transferring, smoke left behind rather than carried — changes what is rendered. Reference tokens @Image1…/@Video1…/@Audio1… address by position — instruct what to DO with a reference, never re-describe it. Likeness/IP blocks are pipeline-level, not prompt-level: photoreal real-person face references are rejected regardless of wording — either switch image→reference mode with the same file (image mode frame-locks, reference mode anchors identity/style) or swap in an AI-generated portrait from generate_image; AI-generated, stylized, illustrated, and 3D-rendered references pass. Named teams, leagues, studios, and copyrighted characters also trip filters — rewrite as a descriptive equivalent that keeps the cultural signal without the trademark. ByteDance moderates outputs, not just inputs: generated audio is the family's most common rejection — a run whose audio trips the filter fails whole, after generation. When a brief fails repeatedly on audio moderation, regenerate with generateAudio=false and layer voice/music post-hoc instead of re-rolling. Output moderation also false-positives on clean video — a "copyright"-class rejection of a render containing no real-world IP clears on one identical resubmit; treat a second identical failure as real and re-plan.

**Prompt rules:** self-contained, no conversation refs (see TOOLS).

**Limitations:**
Mode-gated fields: each mode accepts a specific field set. Per-model caps: Seedance 2.5 ≤30 refs, Gemini Omni Flash ≤10 images plus ≤3 videos of ≤3s each, Seedance 2.0 ≤9, WAN 3.0 ≤10 refs plus ≤5 videos and ≤5 audio, Grok ≤7, Kling 4.0 ≤7 elements plus ≤10 images, flux_3_max ≤8 midFrames. cfgScale/multiPrompt/elements/audioUrl/referenceAudioUrls/midFrames/referenceVideoUrls/referenceFileUrl/referenceWebUrl are model-restricted — validation rejects incompatible combos.

**Models:**
The roster splits by what a model does to its source — some carry its idiom, some render it as film — and each rewards a different prompt grammar:
- **bytedance_seedance_2_5**: Modes: text, image, keyframe, reference. Widest input surface (30 refs), up to 30s, carries the source idiom.
- **bytedance_seedance_2_0**: Modes: text, image, keyframe, reference. Accepts real-person references, up to 15s, carries the source idiom.
- **bytedance_seedance_2_0_fast**: Modes: text, image, keyframe, reference. Seedance grammar at 720p, velocity tier.
- **bytedance_seedance_2_0_mini**: Modes: text, image, keyframe, reference. Cheapest Seedance tier, 720p, rejects real-person references.
- **kling_v3_std**: Modes: text, image, keyframe. Cinematic motion and physics from one anchor; renders as film.
- **kling_v3_pro**: Modes: text, image, keyframe. Multi-shot cinematic consistency; renders as film.
- **kling_v4**: Modes: text, image, keyframe, reference. Shot lists up to 30s, 7 elements plus 10 images, 720p or 1080p, sound on every clip.
- **gemini_omni_flash**: Modes: text, image, keyframe, reference. Prose-directed beats, native audio, end frames, mixed references, 360p to 4K.
- **grok_imagine_video_v1_5**: Modes: text, image, reference. Stylized generalist with native audio.
- **flux_3_max**: Modes: text, image, keyframe. Post-trained FLUX 3: frame pinning via midFrames, 5-20s, 720p/1080p.
- **alibaba_wan_3_0**: Modes: text, image, keyframe, reference. Widest reference mix (video, audio, docs, web), 3-30s; unproven for style preservation.
- **alibaba_wan_3_0_prime**: Modes: text, image, keyframe, reference. WAN 3.0 latency tier — same contract at 1.4x the price.
- **minimax_h3_max**: Modes: text, image, keyframe. Seconds-fast text, image and first/last-frame video, 5-15s, up to 1080P; invents brand text without a product image.
- **luma_ray_3_2**: Modes: text, image, keyframe. Ray 3.2 text, image and first/last-frame video; 540p-1080p SDR MP4.
- **runway_gen4_5**: Modes: text, image. Runway Gen-4.5 text or one-image video, 3-10s standard MP4.
- **kandinsky_6_pro**: Modes: text, image. Kandinsky 6.0 Pro: 5s 480p clips with sound generated with the picture; the dear tier.
- **kandinsky_6_lite**: Modes: text, image. Kandinsky 6.0 Lite: cheap 5s 480p clips with sound, for fast iteration.
- **veed_fabric_1_0**: Modes: image. Audio-driven lip-sync from a still image.
- **bytedance_omnihuman_v2**: Modes: image. Talking video from one image and an audio track; head, face and body follow the speech.
