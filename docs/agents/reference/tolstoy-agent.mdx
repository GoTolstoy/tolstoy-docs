## list_bots

<Note>
  On Claude, this tool is listed only for workspaces allowed to generate media. See [Claude](/agents/connect#claude).
</Note>

Lists the workspace's bots, each with its chatId, name, whether a turn is running, when a person last wrote to it, and its platform link. A bot is a Tolstoy Agent chat that the brand set up with a name and a standing job, such as an Ads Manager or a Creative Director; it keeps its own files and memory across tasks. It only reads.

<Accordion title="Input schema">

```json
{
  "type": "object",
  "properties": {},
  "additionalProperties": false,
  "$schema": "http://json-schema.org/draft-07/schema#"
}
```

</Accordion>

## run_agent

<Note>
  On Claude, this tool is listed only for workspaces allowed to generate media. See [Claude](/agents/connect#claude).
</Note>

Sends a message to the Tolstoy Agent, the workspace's agent, and returns once the turn has started; the answer is read from the chat. The agent answers in text: it plans content and campaigns, writes briefs and scripts, researches the brand and its market, and reads store analytics, in one chat that continues across turns. A turn spends credits.

<Accordion title="Input schema">

```json
{
  "type": "object",
  "properties": {
    "message": {
      "type": "string",
      "minLength": 1,
      "description": "The user's request, in their own words."
    },
    "chatId": {
      "type": "string",
      "minLength": 1,
      "description": "The chat to continue. A bot's chatId from list_bots sends the message to that bot, which works on it with its own job, files and memory. Without it, a new chat starts."
    }
  },
  "required": [
    "message"
  ],
  "additionalProperties": false,
  "$schema": "http://json-schema.org/draft-07/schema#"
}
```

</Accordion>

## get_agent_chat

<Note>
  On Claude, this tool is listed only for workspaces allowed to generate media. See [Claude](/agents/connect#claude).
</Note>

Reads a Tolstoy Agent chat: whether its turn is waiting, running or done, the agent's answer for a finished turn, the images and videos that turn made, and the credits it used. A bot can hand a task to a job chat and end its turn; the task's result then arrives in a later turn of the bot's chat, which a read without messageId returns. It only reads.

<Accordion title="Input schema">

```json
{
  "type": "object",
  "properties": {
    "chatId": {
      "type": "string",
      "minLength": 1,
      "description": "The chat to read."
    },
    "messageId": {
      "type": "string",
      "minLength": 1,
      "description": "The message whose turn to read. Without it, the latest turn is read."
    },
    "wait": {
      "type": "boolean",
      "description": "Wait up to about 50 seconds for a running turn to end. Defaults to false."
    }
  },
  "required": [
    "chatId"
  ],
  "additionalProperties": false,
  "$schema": "http://json-schema.org/draft-07/schema#"
}
```

</Accordion>

## stop_agent

<Note>
  On Claude, this tool is listed only for workspaces allowed to generate media. See [Claude](/agents/connect#claude).
</Note>

Stops the running turn of a Tolstoy Agent chat, the way Stop does in the Tolstoy platform. A generation already sent to a provider still finishes and is billed.

<Accordion title="Input schema">

```json
{
  "type": "object",
  "properties": {
    "chatId": {
      "type": "string",
      "minLength": 1,
      "description": "The chat whose running turn to stop."
    }
  },
  "required": [
    "chatId"
  ],
  "additionalProperties": false,
  "$schema": "http://json-schema.org/draft-07/schema#"
}
```

</Accordion>
