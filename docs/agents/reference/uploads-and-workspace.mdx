## start_media_upload

Starts an upload of a local image or video file to the workspace Library. It creates the Library item, whose id is assetId, and returns a signed transfer plan of shell commands that send the file's bytes straight to storage, so the file never passes through the model. &lt;PATH_TO_FILE&gt; in a command stands for the local file path. A single plan is one curl command. A multipart plan has one command per part: part i sends partSize bytes of the file, from byte i × partSize, to partUrls[i]. The transfer host can refuse a request. The item is unfinished until its upload is finished.

```json
{

  "properties": {
    "fileName": {
      "type": "string",
      "minLength": 1,
      "maxLength": 200,
      "description": "The file name, with its extension."
    },
    "assetType": {
      "type": "string",
      "enum": [
        "image",
        "video"
      ],
      "description": "The real kind of the file."
    },
    "contentType": {
      "type": "string",
      "minLength": 1,
      "description": "The exact MIME type, such as image/png, image/jpeg, video/mp4 or video/quicktime."
    },
    "sizeBytes": {
      "type": "integer",
      "exclusiveMinimum": 0,
      "description": "The exact file size in bytes."
    }
  },
  "required": [
    "fileName",
```

## finish_media_upload

Finishes a Library upload after every request of its transfer plan succeeded. Returns the Library item id (assetId), its media id (mediaId) and its status; the item is done once its media is processed. Calling it again after a success returns the same item.

<Accordion title="Input schema">

```json
{
  "type": "object",
  "properties": {
    "assetId": {
      "type": "string",
      "format": "uuid",
      "description": "The assetId of the upload plan."
    },
    "uploadId": {
      "type": "string",
      "minLength": 1,
      "description": "The uploadId of a multipart upload plan."
    }
  },
  "required": [
    "assetId"
  ],
  "additionalProperties": false,
  "$schema": "http://json-schema.org/draft-07/schema#"
}
```

</Accordion>

## upload_media_from_panel

Puts the user's own images and videos in the workspace Library. With files, saves each image or video the user attached to this chat as one Library item and returns its Library id (assetId), media id (mediaId), assetType and URL; generation tools take an image's URL as a reference image. A file that is not an image or video or cannot be downloaded is listed in notSaved with the reason. Without files, opens a file picker in the Tolstoy panel, where the user picks images or videos from their device. The panel uploads each file to the Library, then posts a message with the Library id and the media id of every file that arrived.

## switch_workspace

Binds this connection to another Tolstoy workspace the user is a member of. Every later call on this connection reads the new workspace: its brand profile, store catalog, media Library, saved models, templates, projects and credits. The team resets to the new workspace's Main team, and the store to its first connected store. Ids read from the previous workspace do not resolve in the new one. Other apps connected to Tolstoy keep their own workspaces.

<Accordion title="Input schema">

```json
{
  "type": "object",
  "properties": {
    "appKey": {
      "type": "string",
      "minLength": 1,
      "description": "The appKey of the workspace, from list_workspaces."
    }
  },
  "required": [
    "appKey"
  ],
  "additionalProperties": false
}
```

</Accordion>
