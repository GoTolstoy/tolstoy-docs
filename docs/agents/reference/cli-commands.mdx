### ai-widgets search-chats

Semantic search over prior chats and their images and assets. The CLI inherits the current chat team; without an explicit team or inherited context, it searches the teams available to the caller. Use it whenever the user refers to an earlier conversation, decision, draft, brief, headline, file, image or asset. Results carry chat IDs for read-chat --chat-ids.

```text
USAGE:  tolstoy ai-widgets search-chats [flags]

FLAGS:
  --team-id       Search this team only. Null selects Main; omitted searches the teams available to the caller.
  --query         Natural language description of the prior conversation or image you are trying to recall (required)
  --title         Optional filter. Only search the chats whose current name contains all of these words.
  --source-types  Optional filter. Defaults to both chat_turn (conversation) and chat_image (generated/uploaded images). (json)
  --max-results   Maximum number of results (default 6, max 12) (number, default: 6)
  --timeframe     How to weight recency. 'recent' (default) biases toward newer chats among comparably-relevant results. Use 'any' only when the user wants the FIRST/oldest occurrence or the whole history regardless of date (e.g. 'the first time we talked about…', 'way back when'). (values: recent, any, default: "recent")
  --after         Optional ISO date/datetime. Only return chat content created on or after this. Set it when the user names the start of a period — resolve relative dates ("since March", "this week") to an absolute date using today's date.
  --before        Optional ISO date/datetime. Only return chat content created on or before this. Use with/instead of `after` for a bounded window ("in March", "last spring", "yesterday").

SCHEMAS (TypeScript):
  --source-types
  type sourceTypes = ("chat_turn" | "chat_image")[];
```

### ai-widgets stop-subagent-chats

Stops sub-agents that --chat-id started, together with every chat they started in turn. A queued sub-agent does not run, and a running turn ends as stopped. Messages from agents that wait in a stopped chat (send-message-to-chat messages and sub-agent run results) do not run; the response lists them under clearedMessages, with the text of each chat message. A result of a stopped sub-agent run that reaches a stopped chat later does not start a turn there either. Messages from a person, Slack, a schedule or a service still run, and so does any message sent to the chat after the stop. --subagent-chat-ids limits the stop to those chats and the chats below them. The run result still arrives in --chat-id when the run has ended, and it reports each stopped sub-agent as failed. A spawn-subagents item with the chatId of a stopped chat continues it.

```text
USAGE:  tolstoy ai-widgets stop-subagent-chats [flags]

FLAGS:
  --chat-id            The chat that started the sub-agents. (required)
  --subagent-chat-ids  Sub-agent chats to stop, each with every chat below it. Omitted: every sub-agent below chatId. (json)

SCHEMAS (TypeScript):
  --subagent-chat-ids
  type subagentChatIds = string[];
```

## analytics

A store's analytics report: engaged shoppers, opens, orders and attributed revenue of its Tolstoy widgets, and the events it sends with the Tolstoy SDK

### analytics get-store-analytics

The analytics report of one store, read from the same code as the merchant's Analytics page and its export. Every revenue, order, buyer, conversion, AOV or engaged-shopper number you give comes from this report, so the merchant sees the same number in the chat, on the page and in the export. A number you build yourself in SQL has another meaning and will not match. Amounts are in report.currency. This store's domains, headless shop, app traffic and widgets. A shopper who watched a video, finished a try-on or chatted. Autoplay counts only after the shopper interacts, and opens are counted separately. An order counts if the same shopper placed it in this store within the window after a widget open, both in the same period. For conversion, the window starts at engagement. Engaged shoppers who bought within the window after engaging, divided by all engaged shoppers. No daily conversion: engagement and order can fall on different days. Items added to cart from a widget within the window before the order. N/A: no widget add to cart was recorded. Other items a widget showed within the window before the order. Other items in the same order. Direct (In-video + Post-video) + Indirect. Average order value of Tolstoy shoppers compared with the store's other orders. A comparison, not lift. N/A means nothing was measured; 0 is a real zero. Impressions, Plays and Shoppers who wrote show N/A when none was recorded. The overview section holds overview, daily, widgetCatalog, liveWidgetTypes, widgetTypes and widgets; the details section holds topVideos, topProducts, events, tryOn and chat. A section that was not asked for is null. Rows do not add up: one shopper or order can count under several widgets. Widgets that ran on this store in the period or are live, whatever the filters. Live = published and active. Widget type tolstoy-sdk lists the store's own events sent with the Tolstoy SDK. They are not opens, engagement, try-ons, add to carts or revenue.

```text
USAGE:  tolstoy analytics get-store-analytics [flags]

FLAGS:
  --app-url     
  --date-from   (required)
  --date-to     (required)
  --window      (values: 24h, 3d, 7d, 30d, default: "24h")
  --widget-ids  (json)
  --channel     (values: web, app)
  --sections    (json, default: ["overview","details"])

SCHEMAS (TypeScript):
  --widget-ids
  type widgetIds = string[];

  --sections
  type sections = ("overview" | "details")[];
```
