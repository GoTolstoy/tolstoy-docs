### How Tolstoy Handles Consent with Shopify

When Tolstoy runs on a Shopify store:

- If **Shopify’s Customer Privacy API** is present, Tolstoy follows [Shopify’s analytics consent state](https://shopify.dev/docs/api/customer-privacy#check-consent-given).
  - Analytics will be **allowed** when Shopify’s analytics state is anything other than 'no'.
  - Analytics will be **blocked** when Shopify’s analytics state is 'no'.
- If Shopify’s API is **not** present, Tolstoy allows analytics by default unless you explicitly default to reject (see last section).

   

### Reject Cookie Conset programmatically

You can programmatically reject cookies when a user doenst accept analytics cooikes policy like this:

**Reject Policy:**

```javascript
window.tolstoyWidget?.postMessage({ eventName: 'tolstoy_reject_cookie_policy' });
```

   

### Default Reject (No Cookies Until Accept)

If you want Tolstoy to start in a **rejected** state until the user explicitly accepts, set the following before loading the Tolstoy widget script:

```javascript
localStorage.setItem('tolstoy-cookie-policy', 'rejected');
```

Then when a user accpets policy send this:

```javascript
window.tolstoyWidget?.postMessage({ eventName: 'tolstoy_accept_cookie_policy' });
```
   

### The Ecom Analytics SDK

A widget that you build with the [Tolstoy Ecom Analytics SDK](/storefront/widgets-sdk) does not use `window.tolstoyWidget`. The SDK examines consent at each event, in this order:

1. The `tolstoy-cookie-policy` value in `localStorage`: `rejected` blocks analytics, and `accepted` allows it. Your widget sets this value from the consent tool of your store. On Shopify, see [Shopper consent](/storefront/widgets-sdk#shopper-consent).
2. Shopify's Customer Privacy API, if the page already loaded it: the analytics state `no` blocks analytics.
3. Cookiebot (the statistics category) and OneTrust (the performance category, `C0002`), after the shopper answers.
4. If the page loads Cookiebot or OneTrust and the shopper did not answer, analytics stays blocked.
5. With no consent tool and no stored value, analytics is allowed.

The SDK does not load a consent tool and does not wait for one. When analytics is blocked, the SDK sends no event and stores no shopper ID. It drops the events from before consent; it does not send them later.

To start in a rejected state with your own consent banner, set the value before the widget loads, and set it to `accepted` when the shopper accepts:

```javascript
localStorage.setItem('tolstoy-cookie-policy', 'rejected');

// When the shopper accepts:
localStorage.setItem('tolstoy-cookie-policy', 'accepted');
```
