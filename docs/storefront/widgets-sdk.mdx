---
title: "Ecom Analytics SDK"
description: "Record the shopper events of a widget that you build yourself with the Tolstoy Ecom Analytics SDK, link them to your orders, and read the results with the Tolstoy CLI or MCP."
---

An outside widget is a widget on your storefront that Tolstoy did not build: your own quiz, carousel, or video block. The Tolstoy Ecom Analytics SDK records its shopper events. Tolstoy then links those events to your orders and shows the results in the same report as the **Analytics** page, apart from the widgets that Tolstoy built.

<Note>
  The SDK measures widgets on the pages of your own store. Events of an outside widget never count toward Shoppable Videos view billing, and they never change the numbers of your Tolstoy widgets.
</Note>

## Add the SDK

The SDK is an ES module on the Tolstoy CDN. Import it in the code of your widget:

```javascript
import { TolstoySDK } from 'https://widgets-sdk.gotolstoy.com/widgets-sdk.js';

const tolstoy = new TolstoySDK({
  appKey: 'YOUR_APP_KEY',
  widgetId: '01JC8Z6Q4M3T9V2X7B5N1K0RWD',
  analyticsSource: 'size-quiz',
  viteDev: false,
  outsideWidget: true,
});

tolstoy.Analytics.trackEmbedViewOnVisibility(document.querySelector('#size-quiz'));
tolstoy.Analytics.trackSessionStartOnInteraction(document.querySelector('#size-quiz'));
```

| Option | Value |
|---|---|
| `appKey` | The app key of your workspace. It is in the code that Tolstoy shows in **Website setup & tracking**: open a widget, click its status button, and then click **Website setup & tracking**. |
| `widgetId` | One ID for each widget. You choose it, and you keep it the same in each release, because the report groups the numbers by it. It must be a [ULID](https://github.com/ulid/spec) (26 characters, upper case) or 13 lowercase letters and digits. The SDK throws an error for an ID of a different shape. |
| `outsideWidget` | `true`. This marks each event of the widget as an outside-widget event. |
| `analyticsSource` | The prefix of your own event names: `trackEvent('click')` sends `size-quiz.click`. |
| `viteDev` | `true` turns analytics off. In a Vite app, use `import.meta.env.DEV`. |

Call `tolstoy.destroy()` when the widget leaves the page. This sends the events that are in the queue.

## Events and the numbers they give

The report counts these SDK calls. A number stays empty when its events are not sent.

| SDK call | Number in the report |
|---|---|
| `trackEmbedView()` or `trackEmbedViewOnVisibility(element)` | Impressions |
| `trackSessionStart()` or `trackSessionStartOnInteraction(element)` | Opens. An order counts for the widget when the same shopper orders in the attribution window after an open. |
| `trackVideoWatched({ videoId, videoWatchedTime })` or `createNativeVideoAnalyticsSession(context)` | Plays, and engaged shoppers (watch time more than 0) |
| `trackAddToCart({ productId, variantId })` | Add to carts, and in-video revenue for the variant that the shopper orders |
| `productId`, `productIds` or `currentPageProductId` on `trackVideoLoaded` or `trackVideoWatched`, and `currentPageProductId` on `trackSessionStart` | Post-video revenue for the product that the shopper orders |
| `trackEvent(name, properties)` | Your own events, listed by name in the details of the report |

Use the product and variant IDs of your store. The SDK changes a Shopify `gid://` ID to its number. A `videoId` must be a UUID, because Tolstoy drops other values.

## Shopper consent

The SDK sends no event and stores no shopper ID until the shopper allows analytics. It drops the events from before that; it does not keep them for later. The SDK follows the Shopify Customer Privacy API, Cookiebot, OneTrust, and the `tolstoy-cookie-policy` value. See [Cookie Consent](/storefront/cookie-consent#the-widgets-sdk).

## Orders

- **Shopify**: Install the Tolstoy app on the store. At the first event that the shopper allows, the SDK writes the shopper ID to the cart attribute `__tolstoyAnonymousId`. Tolstoy reads it from the order.
- **Other platforms**: Add the [conversion tracking code](/storefront/installation#conversion-tracking) to your order confirmation page. It reads the shopper ID that the SDK stores.

Tolstoy links an order only when the shopper used the widget in the same browser.

## Read the results

The report reads tables that Tolstoy builds each night. It covers full UTC days before today. The events of today show after the next build, from about 06:30 UTC.

With the [Tolstoy CLI](/agents/cli):

```bash
tolstoy analytics get-store-analytics \
  --date-from 2026-11-01 \
  --date-to 2026-11-09 \
  --outside-widgets \
  --json
```

- `--app-url` selects a store from `tolstoy stores list`. Without it, the CLI uses your default store.
- `--widget-ids '["01JC8Z6Q4M3T9V2X7B5N1K0RWD"]'` limits the report to some widgets.
- `--window` (`24h`, `3d`, `7d` or `30d`) is how long after an open an order still counts.
- `--sections '["overview","details"]'` adds the details: products, videos and your own events.
- Without `--outside-widgets`, the command reads the widgets that Tolstoy built.

With the [Tolstoy MCP](/agents/connect), the `get_store_analytics` tool returns the same report. Pass `outsideWidgets: true` to read your outside widgets.

In the report, `overview.current` holds the totals, `widgets` holds one row for each widget ID, and `daily` holds the days. An outside widget has no name, so `widgetName` is `null`.

The CLI and the MCP read only the stores of the workspace that you signed in to.
